# りんごのみTV（RingonomiTV）

りんごのみTVは、自分で運用する録画・視聴サーバーに接続するApple TV向けの
オープンソースtvOSアプリです。KonomiTVに加え、MirakurunのTS直接視聴と
EPGStationの番組表・ライブ視聴・録画再生・録画予約・キーワード予約に対応しています。
サーバーURLは初期状態では空で、アプリの設定画面から利用者が入力します。

開発手順は[`CONTRIBUTING.md`](CONTRIBUTING.md)を参照してください。

本アプリは、[Komorebi](https://github.com/BeerEgg2001/Komorebi)の機能と通信仕様を
参考に、Swift／SwiftUI／tvOS向けに再実装しています。参照元Androidプロジェクトの
MIT著作権表示は、このリポジトリの[`LICENSE`](LICENSE)に保持しています。

### 番組表・録画ライブラリ

番組表はチャンネルを横、時間を縦に並べ、朝4時を一日の境界として表示します。左右でチャンネル、上下で番組を選び、決定で詳細を開きます。チャンネル別の一覧表示にも切り替えられます。

- 放送波・日付の切り替え、日本語検索、副チャンネルの表示に対応します。番組詳細から録画予約を追加し、「予約」タブから設定変更・削除ができます。
- キーワード予約は、対象チャンネル、番組長、ジャンル（大分類・中分類）、曜日・時間帯、正規表現・あいまい検索、除外条件を組み合わせられます。曜日・時間帯は日本時間の番組開始日時で判定し、保存前に検索結果を確認できます。
- 録画ライブラリは30件ずつ表示し、番組名・シリーズ名・サブタイトルの部分一致で検索できます。新旧順の並べ替え、チャンネル・ジャンル・曜日・シリーズ別の分類、番組詳細を利用できます。分類対象は最大20,000件です。
- シリーズ情報がない録画は、話数表記を除いた番組名が複数件で一致する場合にまとめ、それ以外は「単発・その他」に表示します。全件表示ではサーバーのページを順に閲覧できます。

通常予約・キーワード予約の保存先と録画後処理は、対応する予約画面で保存先フォルダー、ファイル名テンプレート、ワンセグ用保存先、録画後の動作を設定できます。録画後バッチはサーバー上のパスを接続先ごとに登録して選びます。予約変更画面での保存先・録画後処理の詳細編集UIは未実装です。

### 表示とライブ一覧

設定の「表示」で外観をシステム・ダーク・ライト、配色を標準・春・夏・秋・冬から選べます。番組表の背景・文字・選択枠と再生パネルに反映されます。

ライブ一覧は局名・放送中の番組名・表示番号を検索できます。空白で区切った語はすべてを含むチャンネルに絞り込みます。お気に入りの追加・解除、お気に入りだけの表示、先頭への並べ替えに対応し、お気に入りは接続先ごとにApple TVへ保存します。

### 再生位置・チャプター・PiP

録画の再生位置はApple TVごとに保存します。前回の位置がある録画は続きから再生するか最初から再生するかを選べます。完了間近まで再生した録画は次回に最初から開きます。

- 「チャプター」から本編・CMの開始位置へ移動できます。CM区間情報がない録画では1分戻る・3分進むを利用できます。
- 「シーンサーチ」では、サーバーが生成した時刻付き画像から再生位置を選べます。画像がない場合もシークバーと時間指定の移動は利用できます。
- 「CM自動スキップ」は既定でオフです。完了済みでCM区間情報がある録画のCM終了位置へ移動し、一時停止中・読み込み中・不整合な区間には適用しません。スキップ後30秒以内は元の位置へ戻せます。CM判定はサーバーの解析結果に依存します。
- KonomiTVの録画はPiPに対応します。小窓から一覧操作や全画面への復帰ができ、別の番組を開くと元のPiPを終了して切り替えます。アプリ側のARIB字幕・実況・クロップは小窓には反映されません。ライブや他のバックエンドのPiPは未対応です。

### 音声・実況・字幕

複数音声を認識した配信では再生画面の「音声」から切り替えられます。画質変更後も音声を一意に識別できる場合は選択を引き継ぎます。音声がない、または同名で区別できない場合は案内を表示し、映像は再生を続けます。

- 録画実況は過去ログの表示・非表示、右から流れるコメント、上下の固定コメント、色・文字サイズ、シーク・画質変更後の再同期に対応します。取得に失敗しても映像は再生を続け、メニューから再取得できます。
- ライブ実況は対応チャンネルのNX-Jikkyoから受信し、表示遅延を0〜10秒で調整できます。一時停止・読み込み中は時計を止め、切断時は待ち時間を延ばしながら再接続します。映像の配信遅延は環境に依存するため、放送時刻との厳密な同期ではなく映像に合わせて調整します。
- KonomiTVのライブTS・録画HLSのARIB字幕をlibaribcaptionで描画し、放送指定の色・背景・位置を反映します。「字幕」から表示を切り替えられます。ライブ字幕の同期を戻したい場合は「映像と字幕を再読み込み」を選べます。録画のシークや続き再生の直後は、次の字幕データを受信するまで表示されないことがあります。

再生画面は操作パネルを上下2段に分け、録画の操作ボタンを字幕と重なりにくい上側に配置します。戻るボタンで再生画面を閉じます。

### 接続先

| 接続先 | 主な機能 | 制限・補足 |
| --- | --- | --- |
| KonomiTV | チャンネル・番組表・録画、ライブ／録画再生、予約・キーワード予約、録画PiP、アカウントログイン | リバースプロキシのBasic認証は今後の対応項目です。 |
| Mirakurun | サービス一覧、放送波・日付・検索付き番組表、TS直接視聴 | 画質変更・録画予約には対応していません。チャンネル取得失敗時は取消・再試行を利用できます。 |
| EPGStation | 番組表、録画・動画ファイル選択、予約・ルール予約、ライブ配信、視聴中の画質変更 | 無変換配信を優先し、変換は自動開始しません。詳細な変換設定の編集、ライブ／直接TSの字幕表示は未対応です。録画中ファイルの追従は未検証です。 |
| SMB共有 | フォルダー一覧、ピン留め、認証情報のKeychain保存、動画再生 | 総時間を取得できないTSは時間シークと続き再生に未対応です。認証失敗時の表示と接続方式・ポート制御は改善中です。 |

Mirakurunは、設定またはサービス一覧から放送波・日付を選び、これから始まる番組を検索できます。番組詳細からチャンネルのTSライブ視聴を開始します。再生画面では再生・一時停止と、配信に含まれる複数音声の選択を利用できます。

EPGStationの予約は、番組指定または日時指定、手動予約の末尾切れ設定変更、ルール予約の回単位の除外に対応します。予約一覧は競合・スキップ・重複除外で絞り込めます。キーワード予約は無効状態で作成し、検索プレビューを確認してから保存します。編集しないタグ、保存先、変換設定、サーバー拡張項目は保持します。ルール操作や予約操作で通信結果が不明な場合は自動再送せず、表示された接続先の一覧を更新して確認してから再開します。

EPGStationのライブは無変換配信を優先し、無変換がない場合は変換を自動開始せず画質を明示的に選択します。HLSプレイリストが準備できるまで待機し、準備中・再生中は配信維持要求を送ります。停止・画質変更・再試行では旧配信を停止して準備し直します。

### 接続設定と認証

設定の「サーバーアカウント」からKonomiTVへログインできます。認証情報は接続先ごとにApple TVのKeychainへ保存し、パスワードは保存しません。HTTPS接続を使用し、認証切れは設定から再ログインできます。アカウントなしで利用できる機能はログインせずに利用できます。

SMB共有はフォルダーの追加、一覧、ピン留め、動画再生に対応します。総時間とシーク可否を確認できる動画では「続きから再生」「先頭から再生」を選べます。保存後に再生時間が変わった場合は先頭からの再試行を案内します。

### 再生中の状態表示

再生開始時、画質変更時、再バッファリング時は、映像と音声が利用可能になるまでローディングを表示して音声を出しません。準備中に停止した場合は再生を止め、通信や配信が途切れた場合は再試行または停止を選べます。字幕や実況の処理に失敗しても映像再生は継続し、実況はメニューから再接続・再取得できます。

### 現時点の制限

- ARIB字幕の対象はKonomiTVのライブTS・録画HLSです。複数の字幕言語の選択は未対応で、外字は受信データと描画ライブラリの対応範囲に依存します。
- Mirakurunの画質変更・録画予約、ライブや他のバックエンドのPiPには対応していません。
- EPGStationの詳細な変換設定の編集、ライブ／直接TSの字幕表示、録画中ファイルの追従は未対応または未検証です。
- 予約変更画面での保存先・録画後処理の詳細編集UIは未実装です。SMBで総時間を取得できないTSは時間シークと続き再生に対応しません。

## 準備

Xcode 16.4以降、tvOS 17以降のSDK、Swift 6、macOSを使用します。XcodeGen、
TVVLCKit、libaribcaptionはGitにバイナリを含めていません。大きな依存ファイルを
別ボリュームに置く場合は、準備先を環境変数で指定できます。

```sh
RINGONOMITV_DEPENDENCY_ROOT="$PWD/.cache/dependencies" ./bootstrap.sh
```

`bootstrap.sh`は次の一次配布元から取得し、SHA-256を検証します。

| 依存物 | 取得元 | SHA-256 |
| --- | --- | --- |
| XcodeGen 2.46.0 | [公式リリース](https://github.com/yonaskolb/XcodeGen/releases/tag/2.46.0) / [xcodegen.zip](https://github.com/yonaskolb/XcodeGen/releases/download/2.46.0/xcodegen.zip) | `4d9e34b62172d645eed6457cac13fc222569974098ef4ee9c3368bedf0196806` |
| TVVLCKit 3.7.0 | [VideoLAN公式アーカイブ一覧](https://downloads.videolan.org/cocoapods/prod/) / [TVVLCKit-3.7.0 archive](https://downloads.videolan.org/cocoapods/prod/TVVLCKit-3.7.0-591b8996-f9020c4d.tar.xz) | `de9afabd53b914e234adf39f1f9b7f71d6f8c19bbfc009c8388a2eb0657a16e3` |
| libaribcaption 1.1.2 | [固定コミット](https://github.com/xqq/libaribcaption/tree/37dde0f32652c32aa98bf92278944d1cfb2e7354) / [公式アーカイブ](https://codeload.github.com/xqq/libaribcaption/tar.gz/37dde0f32652c32aa98bf92278944d1cfb2e7354) | `ace54ae69e1b38481917d36161a8960ed93f51f7fd343575fab36dfe3ea072f6` |

TVVLCKitの公式URLが利用できない場合、スクリプトはXcodeGenの準備までを行い、
TVVLCKitは手動配置するよう案内して終了します。推測したミラーや別のURLからは
取得しません。手動配置先は`Vendor/TVVLCKit-binary/TVVLCKit.xcframework`です。
TVVLCKitのソースとライセンスは[VideoLAN VLCKit](https://code.videolan.org/videolan/VLCKit/)
を参照してください。

字幕の描画にはlibaribcaption 1.1.2を固定コミットで使用します。`bootstrap.sh`の最後に
`prepare-captions.sh`が呼ばれ、CMake 3.28以降とXcodeのtvOS SDKで、CoreTextを有効にした
C++17の静的ライブラリをtvOS device arm64、Simulator arm64／x86_64向けに生成します。
FreeTypeとFontconfigは使用しません。2つのSimulatorアーキテクチャを`lipo`でまとめ、
`xcodebuild -create-xcframework`で`Vendor/ARIBCaption/libaribcaption.xcframework`を
作成します。生成物、ソース、アーカイブは`RINGONOMITV_DEPENDENCY_ROOT`（既定は
`.cache/dependencies`）とGit管理外の`Vendor`に置かれます。固定コミットと構成は
`Vendor/ARIBCaption/libaribcaption.version`で確認できます。

libaribcaptionの著作権表示とMITライセンスは
[`App/Licenses/libaribcaption-MIT.txt`](App/Licenses/libaribcaption-MIT.txt)に、内蔵MD5
実装の通知は[`App/Licenses/libaribcaption-MD5-notice.txt`](App/Licenses/libaribcaption-MD5-notice.txt)
に同梱しています。

準備後のSwiftパッケージテストとtvOSビルドは次のとおりです。

```sh
./test.sh
CODE_SIGNING_ALLOWED=NO ./build.sh
```

`build.sh`は`xcode-select`で選択されたXcodeを使います。別のXcodeを使う場合は
`DEVELOPER_DIR`を指定できます。生成される`RingonomiTV.xcodeproj`、TVVLCKit、
ビルド成果物、ログ、キャッシュはGit管理外です。
ソースの追加・更新もXcodeGenのキャッシュで確認し、必要なときにプロジェクトを再生成します。

## Apple TVへの配置

`deploy.sh`の最初の引数はXcodeで確認したApple TVのデバイス識別子です。2番目以降の
引数はそのまま`xcodebuild`へ渡されるため、署名Teamなどのローカル設定をコマンドライン
で指定できます。

```sh
./deploy.sh DEVICE_IDENTIFIER DEVELOPMENT_TEAM=TEAM_IDENTIFIER
```

公開用の既定Bundle IDは`app.ringonomitv.tv`です。既存の個人用インストールを更新する
場合は、Bundle IDを環境変数で指定できます。

```sh
PRODUCT_BUNDLE_IDENTIFIER=your.private.bundle.id \
  ./deploy.sh DEVICE_IDENTIFIER DEVELOPMENT_TEAM=TEAM_IDENTIFIER
```

DEBUGビルドでは、サーバーURLを保存せず実行時引数で指定できます。

```text
--server-url https://example.invalid:7000 --play-channel gr011
```

`--server-url`、`--play-channel`、`--play-recording`、`--show-recordings`、`--show-guide`、`--show-reservations`、障害表示確認用の引数はDEBUG
ビルドだけに含まれます。

## CI

GitHub ActionsではmacOS 15上のXcode 16.4を使い、TVVLCKitバイナリを必要としない
Swiftパッケージテストと通信契約チェックを実行します。TVVLCKitを含むアプリ本体の
署名・実機検証は、各開発者のローカル環境で行います。
非公開リポジトリでは自動CIを抑止し、明示的な手動実行時だけ実行します。

## ロードマップ

現在の着手状況と未完了項目は[進捗管理Issue](https://github.com/g0ooo0gle/RingonomiTV/issues/9)で追跡しています。

1. 起動、バッファリング、画質変更、割り込みからの復帰を安定させる
2. 番組表・検索・録画ライブラリから番組を探す操作を仕上げる
3. 録画予約・キーワード予約の編集と異常時の確認フローを仕上げる
4. 再生位置・チャプター・CMスキップを仕上げ、字幕・実況・主副音声対応を広げる
5. 対応バックエンドとSMBメディアを拡張する
6. L字クロップ・テーマ・二画面・PiP・アプリ内小窓・AI機能を段階的に追加する
7. フォーカス移動、アクセシビリティ、長時間再生、リリースQAと導入文書を仕上げる

各項目は、ユニットテスト、クリーンビルド、対象となるバックエンド・実機確認が
そろった時点で受け入れます。

動作する機能のまとまりごとに、`v0.1.0-beta.N` のような小刻みなベータ版を公開します。
各版のリリースノートで、確認済みの機能、既知の制限、未確認の範囲を案内します。
